# Support Ticket Lifecycle

## Purpose

Orient Support agents to how tickets move through OBO Help and Support / messaging surfaces.

## OBO surfaces (product-derived)

| Path | Label | Use |
| --- | --- | --- |
| `/help-and-support` | Help and Support | Primary support dashboard |
| `/message` | Message | Messaging with users |
| `/contact-management` | Contact Management | Contact / inquiry handling |

Support-role OBO access is typically limited to messaging + interview/support routes — confirm your sidebar.

## Suggested lifecycle (pending ops SLA sign-off)

1. **New** — ticket/inquiry created
2. **In progress** — agent owns and investigates
3. **Waiting** — waiting on customer, engineering, or another queue
4. **Resolved** — fix or answer delivered
5. **Closed** — no further action; reopen only per policy

Exact status names may differ in the live UI — map to the closest equivalent and document the native status in notes.

## DO

- Own the ticket until handoff is explicit
- Link related payment/IDV cases by ID

## DON'T

- Close while waiting on escalation without noting the owner
- Promise SLAs that are not published

## Escalate when

- Payment/IDV/fraud expertise required
- Customer reports safety issues → TNS/fraud routing
