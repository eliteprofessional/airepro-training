# Ticket Escalation SOP

**SOP-SUP-002**

## Purpose

Escalate when Support lacks access, expertise, or when SLA/impact requires specialist queues.

## When to use

- Route access missing for the needed OBO screen
- Payment / IDV / TNS ownership clearer than Support
- Suspected fraud or safety

## Step 1 — Summarize

### Check

- Issue, impact, steps tried, IDs, current status

### Expected result

Receiving queue can act.

## Step 2 — Route

| Topic | Prefer |
| --- | --- |
| Identity documents | IDV / Approve Identity |
| Payment charged/failed | Payments SOPs |
| Withdrawal stuck | OBO withdrawal + payment-airepro ops |
| Suspension / fraud | TNS / Fraud Detection (confirm SoR) |
| Intern conversion | Intern → Freelancer queue |

## Step 3 — Hand off cleanly

### Expected result

Support ticket waiting on named queue; customer informed if appropriate.

## DO

- Escalate with evidence pack
- Keep ownership visible

## DON'T

- Silent drop
- Duplicate escalations without linking
